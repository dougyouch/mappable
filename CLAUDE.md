## Build and Test Commands

```bash
# Install dependencies
bundle install

# Run all tests
bundle exec rspec

# Run a single test file
bundle exec rspec spec/mappable/mapping_spec.rb

# Run a specific test by line number
bundle exec rspec spec/mappable/mapping_spec.rb:42

# Run linter
bundle exec rubocop

# Auto-fix linter issues
bundle exec rubocop -A

# Check API docs (CI requires 100% documented and no warnings)
bundle exec yard stats --list-undoc
bundle exec yard doc --fail-on-warning --no-save --no-output
```

## Architecture

This is a Ruby gem, published as `model-mapper` (module `Mappable`), that maps data from one object to another and back. Speed is the main goal: mappings are compiled into plain Ruby methods, so avoid adding per-field work at map time.

- **Mappable** (`lib/mappable.rb`, `lib/mappable/class_methods.rb`) - included in the source class; `map_to(name) { ... }` creates `<Name>Mapping` as a constant of the class and defines `map_to_<name>(dest)` and `map_from_<name>(src)`.
- **Mappable::Mapping** (`lib/mappable/mapping.rb`) - included in mapping classes; option builders, `create`, and default `map`/`map_back`.
- **Mappable::Mapping::ClassMethods** (`lib/mappable/mapping/class_methods.rb`) - the DSL: `map`, `custom_map`, `custom_map_back`, `mappings`, `map_back_mappings`. Every declaration calls `compile_mappings`.
- **Mappable::Compiler** (`lib/mappable/compiler.rb`) - turns mapping options into method source; procs are stored in the private `MAPPABLE_PROCS` constant on the mapping class.
- **Mappable::Utils** (`lib/mappable/utils.rb`) - `classify_name`.

See ARCHITECTURE.md for details.

### Key Patterns

**Conditions**: `if`/`unless` check the mapping, `if_src`/`unless_src` the object read from, `if_dest`/`unless_dest` the object written to. The reverse mapping built by `map` swaps `_src` and `_dest` conditions (`Mapping::MAP_BACK_CONDITIONS`).

**Inheritance**: uses the `inheritance-helper` gem. Mappings accumulate via `add_value_to_class_method(:mappings, ...)`.

## CI

`.github/workflows/ci.yml` runs RuboCop, a YARD check (100% documented, no warnings), and the specs with `Gemfile.lock` and the 100% line/branch coverage gate on Ruby 3.3 (the gemspec minimum) and on the `.ruby-version` Ruby. On pushes to `master`, it publishes `coverage.svg` (line) and `branches.svg` (branch) from `script/coverage_badge.rb` to the orphan `badges` branch for the README badges.

## Releases

Releases are automated by release-please (`.github/workflows/release.yml`). Conventional commits on `master` (`fix:` → patch, `feat:` → minor, `!`/`BREAKING CHANGE` → major, or minor before 1.0) update an open release PR that bumps `lib/mappable/version.rb` (`Mappable::VERSION`, read by the gemspec) and `CHANGELOG.md`. Merging that PR tags `vX.Y.Z`, creates the GitHub release, and publishes the gem to RubyGems. Don't bump the version by hand.

## Code Commits

Format using angular formatting:
```
<type>(<scope>): <short summary>
```
- **type**: build|ci|docs|feat|fix|perf|refactor|test
- **scope**: The feature or component of the service we're working on
- **summary**: Summary in present tense. Not capitalized. No period at the end.

## Documentation Maintenance

When modifying the codebase, keep documentation in sync:
- **ARCHITECTURE.md** - Update when adding/removing classes, changing component relationships, or altering data flow patterns
- **README.md** - Update when adding new features, changing public APIs, or modifying usage examples
- **YARD comments** - Every public class, module, constant and method needs one; mark internals with `@api private`
- **CHANGELOG.md** - Generated by release-please from commit messages; don't edit by hand except to fix release notes
